# 场所

场所（Place）是量潮知识工作规格的组成部分之一，回答**工作发生在哪里**。本文档定义场所的通用语言、领域模型、领域事件与 API 规格。

## 领域模型

场所组描述工作发生的场所，包括两个层级：

- **工作台**：组织级的共享工作场所，是工作区的容器，同一组织内包含若干工作区；
- **工作区**：材料、产物、工作流、任务等的实际承载空间。
 
工作台与工作区为一对多的层级关系：工作台不直接承载工件与过程，而是通过工作区间接组织它们；材料、产物、工作流、任务必须归属于某一具体工作区，工作台则为其提供组织级的共享与汇总能力。

## 领域事件

本组模型定义场所自身的生命周期事件，并为其他领域事件提供场所上下文。

- **工作台已创建**：某组织建立了共享工作场所，工作台进入可用状态；
- **工作区已创建**：某一工作台内新建了工作区，该工作区进入可承载材料、产物、工作流与任务的状态。
 
工作台已创建通常先于工作区已创建发生：工作区归属于工作台，故其创建事件必以某一已存在的工作台为上下文。

本组事件与其他领域事件的关联如下：

- **工作区已创建 → 材料已收录**：材料只能被收录至已创建的工作区，工作区已创建是材料已收录的前置事件；
- **工作区已创建 → 工作流已创建**：工作流必须创建于某一工作区，工作区已创建亦为其前置事件；
- **任务已启动、任务已完成**：任务隶属于工作流，经由工作流归属于工作区；
- **产物已生成、产物已验收**：产物的生成与验收归属于承载其工作流的工作区。
- 
在首页的典型场景中，用户将材料收录至工作区之前，必然先有该工作区的创建——工作区已创建是整个知识工作事件链的**起点事件**，本规范将其显式定义，使事件链完整。

## API 规格

遵循首页所述 API 设计原则，工作台与工作区作为领域实体均建模为 REST 资源，通过标准 HTTP 方法暴露端点：

- **工作台资源**：支持创建（`POST`）、读取（`GET`）等操作，创建操作对应领域事件“工作台已创建”；
- **工作区资源**：支持创建（`POST`）、读取（`GET`）、更新（`PUT`）等操作，创建时须指定所属工作台，创建操作对应领域事件“工作区已创建”；读取时可返回工作区及其承载的材料、产物、工作流、任务列表。
 
领域服务实现为无状态服务，不维护会话状态。各端点的详细定义见 API 规格明细。
