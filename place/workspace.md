# 工作区

工作区（Workspace）是一次工作的边界：它把一套工作流定义与其上下文内的工件绑定为独立单位。

工作区内，工件与过程互相可见、可流转；工作区之间彼此隔绝。

## 持有

工作区持有三样：

- **坐标**——`root`（工作区根，相对路径的基准）、`data`（数据仓，过程数据与产物的落点）、`workflows`（工作流定义目录）。三处合起来是一次执行的**运行上下文**（Run Context）。
- **定义**——`workflows/` 下的工作流。
- **任务**——`tasks/` 下的任务。

任务只记自己是谁（`name` / `workflow` / 流水 / 闸门 / 产物声明），**不背坐标**——坐标属于工作区，任务离开它就不成立。

## 跨着定义与现场的操作都是工作区的

同一条工作流定义，换个工作区，结论可能不同。定义里判据引用的路径在不在、描述提到的小节有没有覆盖，都要对着工作区核（**核对**）；产物落在哪，要把任务的声明与坐标合起来才算得出（**落点**）；步骤有没有走过，要把任务的流水与它引用的定义合起来才判得出（**流水判定**）。

三件都跨了定义、任务与坐标，所以都是**工作区的操作**，不是定义或任务自身的属性。定义只声明要核什么，工作区提供核的现场。

「在不在」由端侧判断；工作区自身不读文件系统。

## 与工作台

工作台（Workbench）呈现一个或多个工作区，是执行过程的台面。工作区是边界，工作台是台面。工作台是端侧的呈现，工作区是模型。
