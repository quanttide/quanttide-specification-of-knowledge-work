# 工作区

工作区（Workspace）是一次工作的边界：材料、产物、工作流、任务都归属于它；区内工件与过程互相可见、可流转，区间彼此隔绝。

工作区是建模单位，只认内容、不认位置——这些件在物理上从哪来、落在哪，由平台在装载时决定；同一个工作区，资源可以来自多处、任意组合。

## 领域模型

工作区装的是装载起来的定义与任务：定义是工作流，任务是执行实例，各按名字入区、按名字取出。

任务靠 `workflow` 字段按名字指到区内的一条定义。材料与产物不装进模型——它们归属于工作区，落点在用到时按名字算（见 [产物](../piece/artifact.md)）。

## 领域事件

工作区的生命周期事件是工作区已创建（Workspace Created）：平台把定义与任务装载入区，即成立一个工作区。

工作区已创建先于其他各组的事件——材料、工作流、任务、产物都承载于工作区之内。

## API 规格

工作区的操作分两类：装区与取件，以及三件跨着定义与现场的操作。

- 装区：拿装载好的定义与任务装一个工作区；
- 取件：按名字取定义、按名字取任务；
- 核对：判据里的路径在不在、描述提到的小节有没有覆盖，「在不在」由平台判断（规则见 [工作流](../process/workflow.md)）；
- 落点：算一件产物落哪，给相对工作区根的路径，并把判据里的占位换成落点（规则见 [任务](../process/task.md)）；
- 流水判定：按任务流水算走过哪几步、下一步是哪，以及给用户看的一句话（读法见 [任务](../process/task.md)）。
