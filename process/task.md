# 任务

任务（Task）是过程的执行：一条工作流从开工到收工的一次经历。它照定义把各步走一遍，把经过记成流水。

任务是运行数据：程序自己的账，不是产物。

## 领域属性

### 字段

任务落成一份 YAML 文件，一个任务一个文件，文件名即任务名：

- `name`（String，必选）：任务名，在其所属工作区内唯一。
- `workflow`（String，必选）：执行的工作流名。
- `start`（Datetime，必选）：开工时间。
- `log`（List，必选）：流水，只增不改；一条四项——`at` 时刻、`step` 步骤名、`detail` 一句话、`ok` 是否成功。
- `gates`（List，推荐）：闸门项，等人拍板的事项，默认为空。
- `artifacts`（Mapping，推荐）：这次执行往哪写产物，以产物名字为键、落点路径为值（`report`、`journal`），默认为空。

### 关联

一件任务只执行一条工作流，一份工作流可以起多件任务；`workflow` 是两者唯一的链接，名字在区内解析（见 [工作区](../place/workspace.md)）。

产物写在哪由 `artifacts` 声明：写了路径，起任务时按它备好空骨架，判据里的 `{{report}}` 一类占位换成它；没声明就不备骨架，落点也算得出：`artifacts/<产物的名字>/<任务名>.md`，流水就是任务文件本身 `tasks/<任务名>.yaml`。占位换成哪里，判据就核哪里；写产物内容的是人或智能体，程序只维护任务文件。

落点只给相对工作区根的路径，声明成绝对路径就原样；拼上目录是平台的事，末尾斜杠忽略、重复斜杠折叠（`/w/data/` 与 `/w/data//` 都当 `/w/data` 用）。

### 约束

- 位置不进模型：任务文件里不写自己在哪（见 [工作区](../place/workspace.md)）；
- 不校验语法：字段缺了、取值不对一律按空算——`log` 不是列表当空，`gates` 里的非字符串项丢掉，`artifacts` 不是映射当空，流水一条也同理；
- 走过由流水对定义读出：
  - 不带后缀的流水是这一步的执行，重走一遍作废此前的结论、以新的一条为准；
  - 带后缀的流水是对这一步的投票：智能体审查记 `·审`，机器判据记 `·判`；
  - 执行与各项审查都成功，才算走过。
- 步骤认定义：工作流里没有的步骤名，流水里有也不算数；步骤顺序只认定义里的顺序，与流水出现的次序无关。

## 领域事件

### 事件

- 任务已启动（`TaskStarted`）
- 任务已完成（`TaskCompleted`）

### 约束

- 事件负载至少携带任务名与工作区 `id`，供下游投影、汇总与审计使用。

## API端点

任务建模为 REST 资源，端点挂载于工作区之下：任务认名字，跨区互不可见。

### 任务资源端点

- `POST /workspaces/{workspace_id}/tasks`：起任务。
- `GET /workspaces/{workspace_id}/tasks`：列出工作区下的任务。
- `GET /workspaces/{workspace_id}/tasks/{name}`：读取单个任务。
- `PATCH /workspaces/{workspace_id}/tasks/{name}`：更新任务。

### 子资源端点

任务不设子资源端点：产物归工作区，`artifacts` 只声明落点。

### 约束

- 起任务撞上区内已有任务名即拒绝，不覆盖；
- 无状态、幂等键等 API 口径见 [工作区](../place/workspace.md)。
