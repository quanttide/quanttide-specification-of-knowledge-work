# 任务

任务（Task）是过程的一次执行实例。

任务有指令：它定义对工件的一次加工。任务在执行中有状态，由人或系统推进，直至交付对应的工件。

## 语法

任务是一份 YAML，一个任务一个文件，文件名即任务名。

```yaml
name: 任务名
start: 2026-09-10 22:31
workflow: 工作流名
log:
  - at: 2026-09-10 22:32
    step: 步骤名
    detail: 一句话
    ok: true
```

字段：`name`、`start`、`workflow`、`log`（流水）、`gates`（闸门项）、`artifacts`（这次执行往哪写产物，可省）。位置不进模型——任务文件里不写自己在哪（见 [工作区](../place/workspace.md)）。

`workflow` 指向它执行的工作流，是任务与工作流之间唯一的链接；`start` 记开工时间。

流水一条四项：`at` 时刻、`step` 步骤名、`detail` 一句话、`ok` 是否成功。流水只增不改；步骤是否走过，由流水读出。等人拍板的事项记在 `gates` 里。

读法：`step` 不带后缀的流水是这一步的执行，重走一遍就作废此前的结论、以新的一条为准；带后缀的流水是对这一步的投票——智能体审查记 `<步骤>·审`，机器判据记 `<步骤>·判`——与执行结论取合，执行与各项审查都成功才算走过。

工作流里没有的步骤名，流水里有也不算数。步骤顺序只认定义里的顺序，与流水出现的次序无关。

任务不校验语法：它是运行数据，不是定义。字段缺了、取值类型不对，一律按空算——`log` 不是列表当空，`gates` 里的非字符串项丢掉，`artifacts` 不是映射当空——不报错，流水一条也同理。有语法可查的是工作流定义（见 [workflow.md](./workflow.md)）。

任务是运行数据，不是产物：报告、日志这些产物与任务没有从属关系——一次执行可以一份产物都不出，一份报告也可以汇总几件事。程序只维护任务文件，不往产物里写字。

产物写在哪由 `artifacts` 声明（`report: <路径>`、`journal: <路径>`）；写了路径，程序就按它在起任务时备好空骨架、并把判据里的 `{{report}}` 一类占位换成它；没声明就不建产物。

没声明的产物也要算得出落点：报告与日志落 `artifacts/<种类>/<任务名>.md`，流水就是任务文件本身 `tasks/<任务名>.yaml`。占位换成哪里，判据就核哪里。写产物内容的是人或智能体，不是程序。

落点是拼出来的：**目录 + 剩下的路径**。目录由平台给出。相接时两条规范化——**末尾斜杠忽略、重复斜杠折叠**（`/w/data/` 与 `/w/data//` 都当 `/w/data` 用）；相对目录按原样接。目录写成空串，与写成 `/` 等价。
