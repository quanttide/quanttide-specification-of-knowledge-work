# 工单

工单（WorkOrder）是一次行程的封面：一张账本，封皮上写着走哪条工作流、从哪一站起程，内页是流水。工单是账本的户口——只增不改的纪律从封面贯彻到内页：**封面落笔即封，内页只进不出**（见 [工作记录](./work-record.md)）。
工单没有状态字段。走到哪一步、走完没走完，是流水对照定义**推导**出来的，不是填出来的——这条原则在工单这一层兑现得最彻底：连“完结”都不落字段、不发事件，只是一条随时可重算的推导结论。

## 领域属性

### 字段

- `id`（String，必选）：凭证号，UUID，系统生成，全局唯一，落笔后永不改变。跨区引用认它——事件负载、跨区归并、审计追踪，一律凭 `id`。
- `name`（String，必选）：工单名，**工作区内唯一**。人读身份——URL、列表、人话里叫它。名字不跨工作区唯一，也不必：它的辖区就是这一间工作区。
- `description`（String，推荐）：一句话任务，写这单**要干什么**，给执行的人（含智能体）看。工单侧唯一的自由文本。方向向前说——“迁移旧库到新集群”是任务，“已迁移完成”是结局，结局只许出现在流水里。
- `workflow_id`（UUID，必选）：所引工作流的全球凭证，**账本方查填**，请求里带了即拒绝。这枚锚是封条的封泥——`workflow_id` 一旦落笔，所引定义即冻结不可变（见 [工作步骤](./work-step.md)），工单流水此后逐站对账，对的是死的。
- `created_at`（String，必选）：何时开的单。

### 关联

工单从属于工作区，按名引用本工作区的一条工作流、按名指认定义里的一站。三处关联各有一句纪律：
- **对工作流，是钉死**：`workflow_id` 落笔即定义冻结——改步骤、删步骤、调次序，另立新工作流；旧定义原样保留给这本账对到底（见 [工作步骤](./work-step.md)）。未被引用的工作流才可修改，不可变性跟随第一个工单生效；
- **对起点，是闭环**：流水非空时，首条记录的 `step` 须等于 `start`、`step_id` 须等于 `start_id`——对不上即报警，要么声明错了，要么账被动过了；
- **对流水，是封面**：`records` 内嵌于工单，随工单存取；流水的读写走工作记录的子资源端点（见 [工作记录](./work-record.md)），工单本体不开流水的写口。
工单的“走完”是一段推导，不是一枚字段：**流水对照定义逐站对账——每个必经步骤都有 `is_succeeded` 为 `true` 的记录、闸门步骤的放行出自人**，三条齐了，这单走完。结论随时可重算，重算即真相，无须任何人在任何地方“标记完成”——**完成不是动作，是事实**。

### 约束

- 字段取值之外一律拒绝：不认识的字段、缺必填字段，均视为不合语法；
- **封面落笔即封**：`workflow`、`workflow_id`、`start`、`start_id`、`description` 一经创建不可改——改任务、换行程，正确方式是另开工单，旧单留档。工单是账本的封面，封面不改，内页的账才有着落；
- `name` 工作区内唯一，`id` 全局唯一，重名撞号即不合语法；
- `workflow` 须是本工作区内存在的工作流，`start` 须是其所引工作流内的步骤名，写不出处的不收；`workflow_id` 与 `start_id` 由账本方查填，请求自带即拒绝；
- **有账不销**：流水非空的工单不可删除——账本不销户；流水为空的工单（开了单没动工）可删，删的是一张白纸，不欠历史任何东西；
- 进度与完结只许推导，不许落字段：任何把推导结论写回工单的动作，均视为不合语法。
 
## 领域事件

### 事件

- 工单已创建（`WorkOrderCreated`）
### 约束
- 事件负载至少携带工单 `id` 与 `name`、工作区 `id`、`workflow_id`、`start_id` 及声明全文——双锚随单走，跨区下游凭 `id` 直认，凭名字读；
- **无完结事件**：走完没走完是推导，不是事实发生——事实（每一步的发生与放行）已由 `WorkRecorded` 逐条记讫，完结只是这些事实的汇总裁决。下游要“完结”投影，吃流水自己推；账本不发裁决，只记账；
- 下游按工单 `id` 去重：同一 `id` 的创建事件重放视作重放，幂等消化。
 
## API端点

### 资源端点

- `POST /workspaces/{workspace_id}/workorders`：开工单。请求自带 `name`、`workflow`、`start`、`description`、`created_at`；`id`、`workflow_id`、`start_id` 由账本方查填，请求里带了即拒绝——凡账本发的号，不许提交者带。
- `GET /workspaces/{workspace_id}/workorders`：列本工作区的工单，支持 `?workflow_id=` 筛读。
- `GET /workspaces/{workspace_id}/workorders/{name}`：读取工单全貌——封面加全量流水，一次取齐，重放者不必二次请求。
- `GET /workspaces/{workspace_id}/workorders?id={id}`：跨区机器凭凭证寻址。

### 约束

- **不设 PUT**：封面落笔即封，改声明的口子一个不开；
- **不设 DELETE 于有账之单**：流水非空即拒绝删——账本不销户；流水为空可删，删白纸不算改账；
- 工单的进度与完结不在响应里单设字段，由读取方按流水推导——接口只供货，不发结论；
- 流水的追加与读取走子资源端点（见 [工作记录](./work-record.md)），工单本体不代理；
- 无状态、幂等键等 API 口径见 [工作区](../place/workspace.md)。
