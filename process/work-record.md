# 工作记录

工作记录（WorkRecord）是工单流水里的一条：什么时候、哪一步、一句话、过没过。流水是工单的账，工作记录是账上的一笔——只增不改，一条记一件事（见 [工单](./workorder.md)）。

## 领域属性

### 字段

工作记录不独立落盘，内嵌在工单的 `records` 字段里（见 [工单](./workorder.md)）：
- `at`（String，必选）：什么时候。取时间戳，记录写入的时刻。
- `step`（String，必选）：哪一步。须是所引工作流里的步骤名。
- `detail`（String，推荐）：一句话，记这一步发生了什么，给事后重放的人看，默认为空。
- `ok`（Bool，推荐）：过没过，缺省 `false`——没记录“通过”，就当作没通过。
一条工作记录是**最小证据单元**：`at` 答“何时”，`step` 答“何事”，`detail` 答“何情”，`ok` 答“何断”。四样合起来，回答的是验收时的那个追问——它是按哪条定义走的、每一步谁过的。

### 关联

工作记录从属于工单，是工单流水的组成单元。`step` 按名字指向所引工作流的步骤（见 [工作流](./workflow.md)），两相对照即得执行进度——**工单没有状态字段，走到哪一步，就是流水对照定义推导出来的**。
工作记录是程序自己的账：程序记它，人签它（闸门放行也落一条），但它不是产物——账不篡改货，货不替账作证。`ok` 的取值来源只能是机械比对或人经闸门的放行；执行者（含智能体）把 `ok` 写成 `true` 来自我放行，无效。

### 约束

- 字段取值之外一律拒绝：出现不认识的字段、缺必填字段，均视为不合语法；
- **只增不改**：工作记录一旦落笔，修改、删除、重排均视为违规——改结论的唯一方式是追加一条新记录，旧记录原样保留，“以最新一条为准”只是推导规则，不是销毁历史；
- 追加须序：新记录的 `at` 不得早于末条的 `at`，时间倒流的账本不可信；
- `step` 须是所引工作流里的步骤名，写不出处的不收；
- 流水非空时，首条 `step` 须等于工单的 `start`——声明的起点与实际的首步对不上，要么声明错了，要么账被动过了，无论哪种都该报警；
- `ok` 缺省按 `false` 断，宁可严不可松。
 
## 领域事件

### 事件

- 工作记录已追加（`WorkRecorded`）
 
### 约束

- 事件负载至少携带工单名、工作区 `id` 与该条记录全文，供下游投影、汇总与审计使用；
- `WorkRecorded` 只描述追加的那一条，不含全量流水——重建靠事件序列回放，不靠快照覆盖。

## API端点

工作记录是工单流水的子资源，只开口接收追加——**不设 PUT 与 DELETE**：流水只增不改，改历史的口子一个不开。

### 子资源端点

- `POST /workspaces/{workspace_id}/workorders/{name}/records`：追加一条工作记录。
- `GET /workspaces/{workspace_id}/workorders/{name}/records`：读取全量流水，按 `at` 序返回。
- `GET /workspaces/{workspace_id}/workorders/{name}/records?step={step}`：按步骤筛读。

### 约束

- 追加撞上时间倒序即拒绝；
- `step` 不在所引工作流内即拒绝；
- 其余写动作（改、删、重排）一律拒绝，无例外；
- 无状态、幂等键等 API 口径见 [工作区](../place/workspace.md)。
