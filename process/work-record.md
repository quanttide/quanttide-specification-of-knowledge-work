# 工作记录

工作记录（WorkRecord）是工单流水里的一条：什么时候、哪一站、一句话、过没过。流水是工单的账，工作记录是账上的一笔——只增不改，一条记一件事（见 [工单](./workorder.md)）。

工作记录与工作步骤是一对镜像：步骤活在声明侧，说**打算**；记录活在事实侧，说**交代**。流水对照定义逐站对账，执行进度由此而来——工单没有状态字段，走到哪一步，是推导出来的，不是填出来的（见 [工作步骤](./work-step.md)）。

## 领域属性

### 字段

工作记录不独立落盘，内嵌在工单的 `records` 字段里（见 [工单](./workorder.md)）：

- `id`（String，必选）：凭证号，UUID，**追加方生成**，工单内唯一，落笔后永不改变。引用认它——闸门放行、事件负载、审计引用一律凭 `id`，不凭位置。
- `seq`（Int，必选）：页码，**账本方分配**，工单内自 1 起严格递增不跳号。排序认它——展示与遍历按 `seq`，UUID 无序，不排序。
- `created_at`（String，必选）：什么时候。取步骤**发生**的时刻，不取落笔时刻——流水是证据链，证据答“何时发生”，不答“何时录入”。
- `step_id`（UUID，必选）：这一站的全球凭证，UUID，与 `step` 指同一站。**跨边界的机器锚点**——下游投影、事件归并凭它直认，不必回查定义。追加时对账一次，落笔后永不失配（见约束）。
- `description`（String，推荐）：一句话证词，记这一步**已发生**之事，给事后重放的人看，默认为空。这是工作记录**唯一的自由文本**——凡能封闭回答的都已是结构字段，进不了结构的到此为止。
- `is_succeeded`（Bool，推荐）：过没过，缺省 `false`——没记录“过”，就当作没过。

### 关联

工作记录从属于工单，是工单流水的组成单元。`step` 与 `step_id` 一同指向所引工作流里的同一步骤（见 [工作步骤](./work-step.md)），两相对照即得执行进度。流水非空时，首条的 `step` 须等于工单的 `start`——声明的起点与实际的首步对不上，要么声明错了，要么账被动过了。
工作记录是**程序自己的账**：程序记它，人签它（闸门放行也落一条，放行记录凭 `id` 指认落在哪一笔之后），但它不是产物——账不篡改货，货不替账作证。`is_succeeded` 的取值来源只有两个：**机械比对，或人经闸门的放行**。

### 约束

- 字段取值之外一律拒绝：出现不认识的字段、缺必填字段，均视为不合语法；
- **只增不改**：一旦落笔，修改、删除、重排均视为违规——改结论的唯一方式是追加一条新记录，旧记录原样保留，“以最新一条为准”只是推导规则，不是销毁历史；
- **凭证与页码各守其职**：同一 `id` 不得出现两条（账被复制，报警），同一 `seq` 不得出现两条（顺序被篡改，报警）；
- `seq` 须严格递增不跳号——`seq` 断档即有账被抽走，宁可报警不可放过；追加方不得自带 `seq`，页码只能记账的发；
- 追加须序：新记录的 `created_at` 不得早于末条的 `created_at`，时间倒流的账本不可信；
- `is_succeeded` 缺省按 `false` 断，宁可严不可松；
- 记录内部引用一律凭 `id`，排序一律凭 `seq`，禁止任何地方凭数组下标说话——下标是实现细节，不进账本的语义；
- **账不动，定义也不动**：记录的名字引用之所以立得住，靠的是所引工作流一经工单引用即不可变——两侧都死了，对账才有死靶子（见 [工作步骤](./work-step.md)）。
 
## 领域事件

### 事件

- 工作记录已追加（`WorkRecorded`）
### 约束
- 事件负载至少携带工单名、工作区 `id`、该条记录的 `id` 与 `seq`、`step_id` 及记录全文——流水里已双落锚点，事件原样带走，跨区下游凭 `step_id` 直认，零回查；
- `WorkRecorded` 只描述追加的那一条，不含全量流水——重建靠事件序列回放，不靠快照覆盖；
- 下游按记录 `id` 去重对账：同一 `id` 的事件重放视作重放，幂等消化，不二次落账。
## API端点
工作记录是工单流水的子资源，只开口接收追加——**不设 PUT 与 DELETE**：流水只增不改，改历史的口子一个不开。

### 子资源端点

- `POST /workspaces/{workspace_id}/workorders/{name}/records`：追加一条工作记录。请求自带 `id`，`id` 即幂等键——同一 `id` 重复追加视作重放，拒绝第二次；`seq` 由账本方分配，请求里带了即拒绝；`step_id` 由账本方按 `step` 对着所引工作流查填，请求里带了即拒绝——双锚之一由账本亲填，另落校验的口子就不开。
- `GET /workspaces/{workspace_id}/workorders/{name}/records`：读取全量流水，按 `seq` 序返回。
- `GET /workspaces/{workspace_id}/workorders/{name}/records/{record_id}`：读取单条，凭凭证号。
- `GET /workspaces/{workspace_id}/workorders/{name}/records?step={step}`：按站名筛读。

### 约束

- 追加撞上 `created_at` 时间倒序即拒绝；
- 追加撞上已有 `id` 即拒绝，视作重放；
- `step_id` 由账本方查填，请求自带即拒绝——校验从“对不上即拒”变为“错填即拒”：账本填的，天然同指；
- 其余写动作（改、删、重排）一律拒绝，无例外；
- 无状态、幂等键等 API 口径见 [工作区](../place/workspace.md)。
