# 工作流

工作流（Workflow）是过程的定义：一串有序的步骤，每步写着谁做与怎么算完。一份定义可以起多件工单，工单照着它走一遍（见 [工单](./work-order.md)）。

## 领域属性

### 字段

工作流落成一份定义：

- `id`（UUID，派生）：工作流的全球凭证，读取时现算，定义不写此字段（见 [凭证](#凭证)）。
- `name`（String，必选）：工作流名，在其所属工作区内唯一。
- `description`（String，推荐）：一句话说清这条工作流干什么，默认为空。
- `steps`（必选）：行程上的各站，按序排列；步骤字段见 [工作步骤](./work-step.md)。

### 凭证

工作流凭证即 `id`：工单封面、事件负载与 API 响应中的 `workflow_id` 即此凭证。由工作区 id 与工作流名派生（uuid5，RFC 4122）：`uuid5(命名空间, "<工作区 id>/<工作流名>")`。命名空间为跨端契约常量，变更须另立 ADR。

- 同一工作区内名字唯一，凭证即唯一；跨工作区同名各得各号，账目不串；
- 读取时现算，不落盘，任何一方不得写回定义；
- 步骤凭证按「工作流凭证 + 步骤名」分层派生；
- 工单封面所引 `workflow_id` 由账本方在开单时查填，落笔即封，定义此后改名不回填（见 [工单](./work-order.md)）；
- 改名即换凭证，是唯一的身份变更通道；改名的前提是尚未被工单引用——定义一经引用即冻结（见 [工单](./work-order.md)）。

### 关联

工作流隶属工作区（见 [工作区](../place/workspace.md)），被工单按名引用（见 [工单](./work-order.md)）。

### 判据

判据挂在步骤上，答「怎么算完」。判据三字段：`executor`、`description` 与判法，`executor` 答谁判，取 `rule`、`agent` 或 `human`：

- `rule` 由程序按字段判，四种判法各取其一：`path`（该路径存在）、`absent`（该路径不存在）、`file` 加 `contains`（该文件含这段文字，两字段成对）、`run`（该命令在工作区根退出码为零）；
- `agent` 与 `human` 只写 `description`，不带判法字段——前者是给智能体的判准，后者是留给人拍板的事项。

### 约束

- 字段取值之外一律拒绝：出现不认识的字段、缺必填字段、取值不在枚举内，均视为不合语法；
- 判据路径相对工作区根，基准由平台给出；写绝对路径则按绝对路径，跨仓库核对用；
- 定义须可对照工作区核对：`description` 里提到的小节须有 `contains` 判据覆盖；核对由端侧执行——规格定判什么，端侧定怎么核。

## 领域事件

### 事件

- 工作流已创建（`WorkflowCreated`）

### 约束

- 事件负载至少携带工作流名、工作区 `id` 与派生的 `workflow_id`，供下游投影、汇总与审计使用。

## API端点

工作流建模为 REST 资源，端点挂载于工作区之下，路径里的 `{workflow}` 即工作流名。

### 工作流资源端点

- `POST /workbenches/{workbench}/workspaces/{workspace}/workflows`：创建工作流。
- `GET /workbenches/{workbench}/workspaces/{workspace}/workflows`：列出工作区下的工作流。
- `GET /workbenches/{workbench}/workspaces/{workspace}/workflows/{workflow}`：读取单个工作流。

### 子资源端点

工作流不设子资源端点：步骤与判据内嵌在定义里。

### 约束

- 不设 PUT 与 DELETE：定义的修改不经服务端——服务端只收新定义、只读存量；
- 创建工作流撞上区内同名即拒绝，不覆盖；
- 读取单个工作流的响应携带派生的 `workflow_id` 与各步骤凭证，供开单引用与跨端对账；
- 无状态、幂等键等 API 口径见 [工作区](../place/workspace.md)。
